## 1. 本阶段目标

在已经完成厂商开发板整包编译、烧录和基础功能验证的前提下，进入 OmniEgo 底板驱动开发阶段。本阶段目标是建立独立的 OmniEgo 板级 defconfig 和 DTS，保持已经验证过的 RK03 核心板 U-Boot 配置不变，并确认新 DTS 能够成功编译进入 `boot.img`。

### 2.4 修正板级配置选择方式

最初使用了：

```bash

```

该命令一度生成了 OmniEgo 配置，但没有可靠切换 SDK 使用的 `output/defconfig` 链接。随后执行 `make kernel` 时，SDK 检测到配置不一致，并从原来的 `mlk_rk03_rk3576_defconfig` 重新生成配置，导致实际仍然编译厂商的 `mlk-rk03-rk3576-linux.dts`。

确认该 SDK 正确的板级配置选择入口为：

```bash
./build.sh omniego_rk3576_defconfig
```

执行后，`output/defconfig` 已正确指向：

```text
device/rockchip/.chips/rk3576/omniego_rk3576_defconfig
```

最终配置核对结果为：

```text
RK_DEFCONFIG="omniego_rk3576_defconfig"

RK_UBOOT_CFG="rk03"
RK_KERNEL_DTS_NAME="rk3576-omniego"
RK_KERNEL_DTS="$RK_KERNEL_DTS_DIR/$RK_KERNEL_DTS_NAME.dts"
```

## 4. 内核构建逻辑

当前构建链路为：

```text
omniego_rk3576_defconfig
        |
        v
output/.config
        |
        +-- RK_CHIP=rk3576
        +-- RK_UBOOT_CFG=rk03
        +-- RK_KERNEL_DTS_NAME=rk3576-omniego
        |
        v
rockchip_linux_defconfig + rk3576.config
        |
        v
Linux Image + rk3576-omniego.dtb
        |
        v
resource.img
        |
        v
FIT boot.img
        |
        v
output/firmware/boot.img
```

`make kernel` 根据 `RK_KERNEL_DTS_NAME` 调用内核目标 `rk3576-omniego.img`。DTC 将顶层 DTS 及其包含的 DTSI 编译为 DTB，随后构建脚本将 Linux `Image`、DTB 和资源文件打包成 FIT 格式的 `boot.img`。

## 6. 编译提示与分析

### 6.1 I2C DTS 警告

日志包含：

```text
gt1x@14: missing or empty reg property
es8388@10: I2C bus unit address format error, expected "11"
```

这些问题来自当前继承的厂商 EVB/RK03 DTSI，没有阻止本次编译。后续处理触摸和音频节点时，必须依据实际器件地址和原理图修正，不能长期忽略。

### 6.2 内核目录缺少 Git 元数据

日志包含：

```text
fatal: not a git repository (or any of the parent directories): .git
```

这是内核构建过程尝试读取 Git 版本信息时产生的提示。厂商 SDK 内核目录没有完整 Git 元数据，但该提示没有中止编译，也不影响本次生成 DTB 和 `boot.img`。

### 6.3 未检测到 IO domains

日志包含：

```text
Not Found io-domains in kernel/arch/arm64/boot/dts/rockchip/rk3576-omniego.dts
```

该提示来自：

```text
device/rockchip/common/scripts/check-power-domain.sh
```

检查脚本未能从最终 DTB 中提取到 `io-domains` 节点。IO 电压域会影响 Wi-Fi、Flash、以太网等接口的 1.8 V/3.3 V 电平，必须结合 OmniEgo 原理图确认，不能直接依据当前 EVB 配置烧录到定制底板。
