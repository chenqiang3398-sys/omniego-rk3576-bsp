# OmniEgo RK3576 开发日志：最小启动 DTS 裁剪与编译审计

- 日期：2026-08-11
- 阶段：阶段 B，最小启动板
- 分支：`board/omniego-minimal-boot`

## 1. 本阶段目标

解除 OmniEgo DTS 对厂商 `MLK-RK03.dtsi` 底板外设合集的依赖，只保留首次 eMMC 启动所需的核心供电、RK806、eMMC 和 UART0，并完成 DTB 与 `boot.img` 编译审计。

## 2. 已完成工作

新增 `rk3576-omniego-minimal.dtsi`，继续复用厂商已验证的 `rk3576-evb.dtsi` 电源基线和 `rk3576-rk806.dtsi`，单独引入 `rk03/mmc.dtsi` 与 `rk03/uart.dtsi`。

首版明确关闭 TF、SDIO、EVB LED、HDMI sound、I2C0 和非必需 Combo PHY，并删除 EVB Goodix 触摸节点。未引入厂商相机、显示、音频、网口、PCIe、RTC、Type-C、RS485、TTL 和 SPI 配置。

为处理厂商公共 DTS 的反向依赖，对保持 disabled 的 SDIO、UART4 和 UART8 删除了指向厂商底板 pinctrl 标签的 `pinctrl-0`，并删除了指向不存在节点的 `spi1` alias。

已将本次 `boot.img` 单独烧入“MLK-CR03 RK3576 核心板 + 米联客厂商底板”，保留原有 Loader、U-Boot、分区表和 Buildroot rootfs。串口日志确认：

本次验证结论：OmniEgo 最小 DTS、RK806、UART0、eMMC 和现有 rootfs 在同款 MLK-CR03 核心板上的启动链通过。该结果不等同于自研底板硬件验证。

## 5. 遗留问题与风险

1. 构建仍提示未找到 `io-domains`。在核心板 IO bank 电压资料确认前不猜测配置。
2. 当前仍复用 `rk3576-evb.dtsi` 中的厂商电源基线；核心板主供电关系明确后再抽取独立 core DTSI。
3. 尚未生成新的完整 `update.img`；本次采用单独烧写 `boot.img` 验证。
4. 自研底板尚无实物，其主供电、UART 走线、USB 恢复链路及底板外设仍未验证。
5. 串口引脚资料已确认 UART0 M0 为 3.3 V，但自研底板最终接口位号和实物电气特性仍需首板复核。
