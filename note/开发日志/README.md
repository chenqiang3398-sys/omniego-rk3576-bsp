# OmniEgo RK3576 开发日志

本目录用于保存各阶段的开发过程记录。一个聊天上下文即将结束时，根据该上下文中的实际工作生成一份独立 Markdown 日志。

## 命名规则

```text
YYYY-MM-DD_两位序号_主题.md
```

示例：

```text
2026-08-03_01_建立OmniEgo板级配置并验证内核编译.md
2026-08-04_02_最小启动DTS裁剪.md
```

同一天存在多份日志时递增序号。文件名中的主题应描述完成的主要工作，避免使用“工作记录”等无法区分内容的名称。

## 记录内容

每份日志至少包含：

1. 本阶段目标。
2. 已完成工作及实际结果。
3. 新增或修改的文件。
4. 使用过的关键命令。
5. 遇到的问题、原因与处理方法。
6. 编译、烧录或板端验证结果。
7. 当前遗留问题和风险。
8. 下一阶段首要任务。
9. 相关 Git 分支、提交和标签（如已创建）。

日志只记录已经发生并能够确认的事实。尚未执行的工作放入“下一步”，不得写成已完成。

## 使用方法

当聊天上下文即将用完时，提出类似以下要求：

```text
请总结当前聊天框完成的工作，并写入 note/开发日志。
```

生成日志后，应检查文件内容，再将 `note/开发日志/` 同步到独立的 BSP Git 仓库并提交。
